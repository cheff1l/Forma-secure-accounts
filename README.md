# Forma — лабораторна робота 6–7

## Проєкт із безпеки: інтеграція в Forma

До наявного сайту тестування додано сервер облікових записів на FastAPI та SQLite. Форма входу й профіль працюють на тому самому локальному адресі, що й React-сайт. Перед відкриттям тестів сайт перевіряє серверну сесію. Кожен обліковий запис має власне сховище демонстраційних тестів у браузері; самі тести, друзі й історія поки залишаються демонстраційними даними MSW/localStorage. Серверна безпека стосується облікових записів, сесій, ролей і журналу входів.

Після входу відкривається один профіль Forma: навчальний прогрес, особисті дані, стан безпеки, активні сеанси та останні події показані разом. У списку сеансів видно браузер, пристрій, IP, час входу й останньої активності; кнопка **Завершити інші сеанси** залишає поточний браузер у системі й відкликає всі інші серверні сеанси. Якщо Vite-проксі передає локальне з’єднання як `127.0.0.1`, профіль окремо показує IPv4-адресу ПК на активному мережевому маршруті. У серверному журналі залишається фактична адреса з’єднання. Це адреса мережевого інтерфейсу, а не обов’язково зовнішня адреса провайдера; браузер і пристрій визначаються за User-Agent. Посилання `/profile` веде на цей профіль. На `/account/settings` можна змінити відображуване ім’я, дату народження, короткий опис і логін для входу. Логін унікальний без урахування регістру; для його зміни власник акаунта з паролем вводить поточний пароль. Email залишається способом входу, а логін адміністратора `admin` закріплений. Реєстрація вимагає повторного введення пароля; сервер також перевіряє збіг.

**Спершу заповніть `backend/.env` за інструкцією [SETUP_EMAIL_CAPTCHA_GOOGLE.md](SETUP_EMAIL_CAPTCHA_GOOGLE.md).** Для реєстрації обов’язкові Gmail SMTP і hCaptcha. Сервісний віджет hCaptcha працює на реєстрації, вході з паролем, вході через Google та сторінці нового пароля; сервер перевіряє його токен через hCaptcha Siteverify. Для віджета форми входу автоматично відкриваються на `forma.localtest.me`; після Google OAuth користувач повертається на `127.0.0.1` зі збереженням сесії. Під час реєстрації пароль і підтвердження можна показати кнопкою з оком. Пароль перевіряється без переходу на сторінку помилки; 2FA вмикається у профілі, відновлення надсилає справжній лист, Google-вхід потребує власних OAuth-ключів.

### Запуск на Windows

Потрібні Python 3.11+ і Node.js 20.19+ або 22.12+. У двох терміналах відкрийте цю папку:

```powershell
# Термінал 1
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
.\.venv\Scripts\python.exe backend\app.py
```

```powershell
# Термінал 2
npm.cmd ci
npm.cmd run dev
```

Відкрийте **http://127.0.0.1:5173**. Backend слухає тільки `127.0.0.1:8000`; Vite пересилає йому маршрути реєстрації, входу, профілю та адміністратора. Якщо Vite запропонує інший порт, звільніть 5173 або змініть `BASE_URL` та дозволений Google redirect URI відповідно.
Якщо `.venv` відсутня на іншому ПК, створіть її командою `python -m venv .venv`, а потім встановіть пакети командою `.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt`.

Для створення адміністратора зупиніть backend і виконайте `python backend/app.py init-admin`. Введіть власний надійний пароль у прихованому запиті, потім запустіть backend знову. На сторінці входу введіть **логін `admin`** і цей пароль. За замовчуванням email адміністратора — `admin@forma.local`; щоб використати власний, виконайте `python backend/app.py init-admin ваша_адреса@example.com`. Повторний запуск команди оновлює пароль адміністратора. Не використовуйте email звичайного демонстраційного користувача для адміністратора.

Адмінпанель `/admin` показує кількість усіх, активованих, заблокованих і захищених TOTP акаунтів; список користувачів із ролями та станом 2FA; блокування/розблокування; останні події та журнал аудиту спроб входу, CAPTCHA, 2FA, відновлення пароля й адміністративних дій. У списку акаунтів показано останній IP успішного входу. Журнал аудиту окремо показує **IP користувача** з його останнього входу та **IP дії**, який належить виконавцю конкретної події. Для локального входу `127.0.0.1` відображається як поточний IP цього ПК з позначкою. Вкладка **Надіслані листи** показує адресата, тему, дату й статус усіх успішних відправлень із пагінацією. Текст листів у робочому режимі не зберігається, щоб не накопичувати одноразові посилання активації та скидання пароля. Після п’ятої невдалої спроби входу до наявного акаунта він блокується на 15 хвилин, а на зареєстрований email надходить попередження з посиланням на `/support`. На сторінці підтримки можна вказати тип проблеми, тему, опис і кроки відтворення навіть без входу. У вкладці **Підтримка** адміністратор відкриває деталі, бачить IP успішних входів і невдалі спроби, змінює статус, залишає службову примітку та надсилає відповідь на зареєстровану адресу. У блоці дій активний акаунт має кнопку **Заблокувати**, а заблокований — **Розблокувати**; блокування завершує всі його сеанси. Видалення потребує введення email і слова `ВИДАЛИТИ`; воно прибирає акаунт, сеанси й токени, але зберігає журнал безпеки та історію листів. ID видаленого акаунта повторно не видається, щоб не змішати його локальні демонстраційні дані з новим користувачем. Email із анонімної форми не вважається підтвердженням власності акаунта. Помилка SMTP фіксується в аудиті, але не скасовує блокування. Доступ до адмінпанелі захищено роллю `admin`.

За замовчуванням демоскринька вимкнена (`DEMO_MODE=0`). Листи йдуть через Gmail SMTP після заповнення `backend/.env`. Якщо SMTP або hCaptcha ще не налаштовано, форма реєстрації пояснить, чого бракує.

### Google OpenID Connect

Створіть OAuth client типу **Web application** у Google Cloud, налаштуйте consent screen та точний redirect URI `http://127.0.0.1:5173/google/callback`. У `backend/.env` заповніть `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` і `BASE_URL=http://127.0.0.1:5173`. Перезапустіть backend. Кнопка Google є на сторінці входу й працює після налаштування. У профілі Forma з’являється дія **Підключити Google-акаунт**: спочатку ввійдіть локальним паролем, а потім виберіть Google-акаунт із тією самою адресою пошти. Після підключення обидва способи входу ведуть до одного профілю. Для демонстрації потрібні інтернет і доступний Google-акаунт. Повернений ID token перевіряється через Google `tokeninfo` з контролем `aud`, `iss`, `nonce`, `exp` і підтвердженого email; для реального виробничого запуску варто перейти на локальну перевірку підпису за JWKS.

### Послідовність відеозвіту

1. Коротко назвіть стек: React/Vite, FastAPI, SQLite, MSW для демонстраційних тестів, `scrypt` для паролів, TOTP для 2FA.
2. Відкрийте реєстрацію. Введіть слабкий пароль, потім валідний пароль і розв’яжіть CAPTCHA.
3. Відкрийте отриманий Gmail-лист, перейдіть за одноразовим посиланням активації. Увійдіть і покажіть статус у профілі, а далі відкрийте тести Forma.
4. Вийдіть. Зробіть 5 невдалих входів у наявний акаунт. Покажіть Gmail-лист із попередженням, відкрийте з нього `/support` на цьому ПК і надішліть звернення. Увійдіть адміністратором в іншому вікні й покажіть вкладки **Надіслані листи**, **Підтримка** та журнал аудиту. Після 15 хвилин тимчасове блокування входу минає; для швидкого показу користуйтеся іншим тестовим акаунтом або адміністраторським розблокуванням.
5. У профілі відкрийте **Редагувати профіль**, змініть логін та ім’я, додайте дату народження й покажіть вхід за новим логіном.
6. Увійдіть у той самий акаунт у другому браузері або в режимі інкогніто. У першому профілі натисніть **Оновити список** у блоці **Активні сеанси**, покажіть обидва записи й натисніть **Завершити інші сеанси**. Оновіть другий браузер: він має повернутися до входу.
7. У профілі ввімкніть 2FA, відсканувавши QR-код або додавши показаний ключ до TOTP-застосунку. Вийдіть і знову ввійдіть із кодом.
8. За наявності Google OAuth client у профілі натисніть **Підключити Google-акаунт**, підтвердьте Google-акаунт із тією самою поштою, потім вийдіть і покажіть вхід через Google до того самого профілю.
9. На сторінці входу натисніть **Забули пароль?**, відкрийте лист, установіть новий пароль і ввійдіть із ним. Повторне використання посилання має бути відхилене.
10. У фіналі покажіть, що тести Forma працюють після входу, і згадайте, що для Google потрібні зовнішні облікові дані, а навчальні тести зберігаються локально в браузері.

Перевірка логіки: `.\.venv\Scripts\python.exe -m pytest -q backend/test_app.py`. Перевірка фронтенду: `npm.cmd run build`. У PowerShell викликайте `npm.cmd`, оскільки `npm` може запускати заблокований політикою Windows файл `npm.ps1`.

> Не публікуйте `backend/.env` та `backend/accounts.sqlite3`. За потреби можна тимчасово ввімкнути `DEMO_MODE=1` для локального тестування без Gmail; для відеопоказу реальних листів використовуйте `DEMO_MODE=0`.

---

Адаптивний фронтенд системи навчального тестування на React і Vite. Інтерфейс оформлений як сучасний навчальний простір Forma Studio з окремими екранами для тестів, проходжень, історії та друзів. Дані тестів залишаються демонстраційними: `fetch('/api/...')` перехоплює браузерний Service Worker бібліотеки MSW, а вони зберігаються у `localStorage`. Облікові записи працюють через Python backend.

## Окремий запуск фронтенду

Потрібен Node.js 20.19+ або 22.12+. Для входу потрібен також запущений Python backend за інструкцією вище.

```bash
npm.cmd ci
npm.cmd run dev
```

Відкрийте адресу, яку покаже Vite (зазвичай `http://127.0.0.1:5173`). Для перевірки збірки: `npm.cmd run build`; для перегляду зібраної версії: `npm.cmd run preview`.

## Сценарії

- **Головна:** підсумок власних тестів, усіх завершених спроб та середній відсоток; нещодавні тести.
- **Тести:** власні, тести підтверджених друзів і вибране; пошук; редагування та видалення власних тестів.
- **Новий тест:** форма з валідацією, вставленням тексту або завантаженням TXT; вибір рівня та кількості питань.
- **Проходження:** вибір відповіді, покрокова навігація, результат і запис кожної спроби.
- **Історія:** усі спроби, включно з повторними; середній відсоток рахується з усіх завершених проходжень.
- **Друзі:** вхідний запит із підтвердженням/відхиленням та надсилання запиту за ім’ям користувача.
- **Профіль друга:** натисніть на друга у списку, щоб побачити його тести, завершені спроби, середній і найкращий результат. Профіль доступний лише підтвердженим друзям.

Адаптивний рівень у демо визначається середнім балом усіх завершених спроб: від 80% — складний, від 60% — середній, інакше легкий. **LLM не підключена.** Демо-генерація створює прості шаблонні питання з речень завантаженого матеріалу. Її результат призначений для перевірки інтерфейсу, а не для реального оцінювання знань. Завантаження файлу підтримує лише TXT до 2 МБ.

## Структура

```text
src/
  App.jsx             екрани та повторно використовувані UI-компоненти
  components/FriendProfile.jsx  сторінка друга
  components/friend-profile.css  адаптивний стиль сторінки друга
  index.css           стиль і адаптивна сітка
  studio-theme.css    візуальна тема Forma Studio
  lib/api.js          клієнтський шар fetch-запитів
  mocks/data.js       початкові дані та localStorage
  mocks/handlers.js   mock REST-ендпоїнти та логіка CRUD
  main.jsx            запуск MSW і React
public/mockServiceWorker.js
```

Дані залишаються у браузері після перезавантаження. Кнопка **Скинути демо** відновлює початковий набір.
